Conventions shared by all samplers

Thermal speeds: theta_perp, theta_par

theta is a thermal speed, not a temperature, and has units of velocity. For the bi-Maxwellian, theta = sqrt(2 k_B T / m) and a velocity component is distributed as N(0, theta^2 / 2). For the bi-Kappa distribution, theta is the scale in its density and is not tied to a temperature, which does not exist for kappa <= 3/2. The bi-Kappa distribution is 

f(v) ~ [1 + v_perp^2 / (kappa theta_perp^2) + v_par^2 / (kappa theta_par^2)]^-(kappa+1)

theta_perp applies to both directions perpendicular to ub and theta_par to the direction along it. Both must be positive.

Field direction: ub

A 3-vector {bx, by, bz} giving the magnetic-field direction in the global frame.

  • It is normalized internally, so it need not have unit length.
  • It must be non-zero.
  • Samples are drawn in field-aligned coordinates and rotated into the global frame before they are returned. For ub = {0, 0, 1} no rotation is applied.

The two perpendicular axes are chosen internally. They matter only for a finite velocity cap, whose box is aligned with them (see The velocity cap).

Seeding and random engines

seed(s) can be called at any time. bi_kappa_distribution and bi_maxwellian_distribution also accept the seed as the last argument of define(...).

Value Effect
s >= 0 The same seed reproduces the same sequence.
s < 0 Seeds from std::random_device.

Without a seed the internal engine is seeded from std::random_device at construction, so runs are not reproducible.

dist(gen) draws from an engine you supply instead of the internal one, for example one std::mt19937 shared by several samplers. For bi_kappa_distribution the engine must produce a power-of-two number of distinct values, as std::mt19937 and std::mt19937_64 do.

For bi_kappa_distribution, a given seed gives the same values under libc++ and libstdc++ on the same architecture. Compile with -ffp-contract=off to rule out differences from fused multiply-add. Values are not bitwise identical across architectures, and they differ from release 1.0.0 (see CHANGELOG.md).

Rejection-sampler settings: probe_points, max_reject_tries

These apply to the three samplers that take a user function (general_velocity_generator, field_aligned_velocity_generator, general_position_generator).

Parameter Meaning Default
probe_points Number of grid points used once, in define(...), to estimate the maximum of your function. The estimate plus a 5% margin is the rejection envelope. 1024 (velocity generators, must be >= 64); 4096 (position generator, must be > 0)
max_reject_tries Candidate draws allowed per sample before operator() throws std::runtime_error. 100000 (velocity generators); 200000 (position generator)
Warning
If your function has a peak narrower than the probe spacing, the estimated maximum is too low and the samples are biased, with no error reported. For a narrow peak, raise probe_points until pdfUpperBound() stops increasing.

If a sampler exhausts max_reject_tries, the function is usually small over most of its range. Narrowing the range is more effective than raising the limit.

define(...) also rejects NaN values, infinite thermal speeds and non-finite ub components.

Moments of order l exist only for kappa > (l + 1) / 2. For 0.5 < kappa <= 1.5 the uncapped distribution has no finite second moment, so a temperature computed from the loaded particles does not converge as the number of particles grows. Use quantiles to characterize such a sample.

Finite precision near kappa = 1/2

As kappa approaches 1/2, the bi-Kappa distribution puts a non-negligible probability on speeds above the largest representable floating-point number. For theta_perp = theta_par = 1 and ub = {0, 0, 1}, this probability is about 8.3e-4 at kappa = 0.505 and 6.8e-7 at kappa = 0.51 in double, and about 1.4e-4 at kappa = 0.55 and 1.9e-8 at kappa = 0.60 in float.

  • Without a cap, such a draw is returned with infinite components.
  • With a cap, it is rejected and redrawn.
  • In both cases n_nonfinite() counts it, and n_attempts() counts every attempt, including draws rejected by the cap. reset(), seed() and define() clear both counters.
  • An overflowing draw sets FE_OVERFLOW and errno = ERANGE.

Compiling with -ffast-math lets the compiler assume that no infinity occurs, so no_cap() and the counters are unreliable in that mode. The header then prints a compile-time note; define BI_KAPPA_ALLOW_FAST_MATH to silence it. A finite cap still works.

The paper's section on finite precision gives the derivation.

The velocity cap

max_normalized_velocity (here cap) is a finite positive value or no_cap(). It works the same way on bi_kappa_distribution and bi_maxwellian_distribution.

With a finite cap, a draw is accepted only if every component lies inside the box 

|v_perp1| / theta_perp <= cap,  |v_perp2| / theta_perp <= cap,  |v_par| / theta_par <= cap

in field-aligned coordinates. Otherwise it is redrawn. The samples therefore follow the distribution conditioned on the box: the density restricted to the box and renormalized. The sampler throws std::runtime_error after 10^6 consecutive rejections.

  • Default. The default cap is 20 thermal speeds. Release 1.0.0 used the same default, so code written against 1.0.0 samples the same distribution.
  • No cap. no_cap() returns +infinity. With it, the sampler draws from the bi-Kappa or bi-Maxwellian distribution itself, with no rejection loop. param().capped() returns true when a finite cap is in force. Passing 0 throws.
  • Effect on bi-Kappa. For kappa <= 3/2 a cap of 20 removes an appreciable part of the high-energy tail. The paper's section on finite velocity bounds quantifies this. The fraction of rejected draws is not a reliable measure of how much of the tail is lost.
  • Effect on bi-Maxwellian. A cap of 20 corresponds to about 28 standard deviations per component and has no practical effect.
  • Frame. The box is aligned with the field-aligned axes and rotates with ub. The returned global-frame components are therefore not individually bounded by cap * theta unless ub = {0, 0, 1}. The speed is bounded in every frame by cap * sqrt(2 theta_perp^2 + theta_par^2).
  • Symmetry. Because the box is a cube in normalized coordinates, the capped distribution is not symmetric under rotation about ub.
using BK = bi_kappa_distribution<double>;
BK dist;
dist.define(2.0, 1.0, 2.0, {0, 0, 1}); // cap = 20
dist.define(2.0, 1.0, 2.0, {0, 0, 1}, BK::no_cap()); // no cap
dist.max_normalized_velocity(50.0); // change only the cap
bool c = dist.param().capped(); // true

general_velocity_generator

define(speed_sq_pdf, speed_sq_min, speed_sq_max, probe_points, max_reject_tries)
Parameter Meaning Default Valid range
speed_sq_pdf Your density g(w) in the speed squared w = \|v\|^2. It need not be normalized. required callable; finite, non-negative, positive somewhere in range
speed_sq_min Lower end of the sampled w. required >= 0
speed_sq_max Upper end of the sampled w. required >= speed_sq_min
probe_points See Rejection-sampler settings: probe_points, max_reject_tries. 1024 >= 64
max_reject_tries See Rejection-sampler settings: probe_points, max_reject_tries. 100000 > 0

The speed is sqrt(w) and the direction is isotropic. The generator takes no mass: for a distribution written in energy, use w = 2E/m. For example, a Maxwellian with thermal speed theta is g(w) = sqrt(w) exp(-w / theta^2), since dw = 2 |v| d|v| and the speed density is |v|^2 exp(-|v|^2 / theta^2).

[speed_sq_min, speed_sq_max] is the support: no sample lies outside it. If speed_sq_min == speed_sq_max, every sample has speed sqrt(speed_sq_min) and g is not evaluated.

This interface replaced the 1.0.0 interface define(f, E_min, E_max, particle_mass, ...). An old four-argument call passes the mass as probe_points, and throws if the mass is below 64.

Every sample has the same sign of v_par, which suits beams and drifting populations. For a symmetric parallel distribution, draw the sign yourself or use bi_kappa_distribution or bi_maxwellian_distribution. If speed_sq_min == speed_sq_max, every sample has parallel speed sqrt(speed_sq_min). Velocities are returned in the global frame.
