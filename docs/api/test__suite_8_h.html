True when this build fuses a multiply and an add into a single rounding.

A fused a*b + c rounds once, so x*x - (1 + 2^-51) with x = 1 + 2^-52 comes out as 2^-104 rather than exactly zero. 16 draws at kappa = 2, theta_perp = 1, theta_par = 2, ub = {0,0,1}, seed 20030410, as exact bit patterns.

ONE array serves both standard libraries: since 2.0.0 the Gamma, normal and uniform primitives live in the header, so the sampled sequence is a function of the engine alone. That equality is not background to this test, it is the assertion – a libstdc++ build that disagreed with the array its build selects would mean the stream had become a property of the standard library again. Each array below was produced identically by libc++ and by libstdc++.

There are two arrays because the stream depends on one thing the standard library is not responsible for: whether the compiler fuses a multiply and an add. A fused multiply-add rounds once instead of twice, and the sampler has several expressions it applies to – 1 - cosTheta*cosTheta and 1 + c*x among them – so a contracting build differs from a non-contracting one by one or two units in the last place on about a tenth of the components. The two toolchains do not default alike: clang contracts at every optimization level, GCC only from -O2. Both settings are frozen here, and a stream matching neither is drift.

Off is what the source text specifies; a project that needs the stream to be a property of the source alone should pass -ffp-contract=off, and that belongs in the library's build documentation rather than in this test.
