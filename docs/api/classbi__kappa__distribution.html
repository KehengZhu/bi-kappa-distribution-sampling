Detailed Description

template<typename RealType = double>
class bi_kappa_distribution< RealType >

Bi-Kappa distribution class for sampling 3D velocity vectors.

This class follows the interface pattern of standard library distributions like std::uniform_real_distribution<T>.

bi_kappa_distribution<double> dist;
dist.define(2.0, 1.0, 2.0, {0, 0, 1}); // kappa, theta_perp, theta_par, ub
auto v = dist(); // {vx, vy, vz}, global frame

Note
The cap defaults to 20 thermal speeds, so the default target is the bi-Kappa distribution conditioned on the component-wise box |v_i|/theta_i <= 20 in field-aligned coordinates. Pass no_cap() to sample the bi-Kappa distribution itself. At kappa <= 3/2 a cap of 20 removes an appreciable part of the tail; see The velocity cap, no_cap() and param_type::capped().
The radius is built in the logarithmic domain. R = sqrt(X1)/sqrt(X2) with X2 ~ Gamma(kappa - 1/2, 1), so as kappa -> 1/2 the denominator's shape goes to zero and X2 underflows to exactly zero. X2 is therefore never formed: the sampler carries log X2 and log R, and reaches the linear domain only at the last step, once per component. Whether a component is representable is then decided from the component itself – the number about to be returned – and never from its logarithm, because log(max()) is a rounded value that can sit on either side of the true limit; see bikappa_detail::materializeComponents. Two consequences a caller should know about:
  • Reproducibility. The Gamma, normal and uniform variates are generated by the code in bikappa_detail rather than by <random>, and the direction is drawn by a rejection method that uses no trigonometric function. A given seed therefore gives bit-identical output under libc++ and libstdc++ on the same architecture. The output still depends on whether the compiler fuses a multiply and an add; pass -ffp-contract=off to rule that out. Across architectures the output is not bitwise identical, because log and exp are not correctly rounded and their implementations differ. CHANGELOG.md lists the versions whose random stream differs.
  • Non-finite output near kappa = 1/2. Sufficiently near kappa = 1/2 the bi-Kappa distribution puts non-zero probability on velocities beyond the largest finite value of RealType. Such a draw cannot be returned as a number. Without a cap it is returned with infinite components, and n_nonfinite() counts it. Because no intermediate of the radius can underflow, these are the only draws lost: in double at kappa = 0.505 they are about 8.3e-4 of all draws. Finite precision near kappa = 1/2 gives more values.
See also
Usage examples for more recipes (seeding, external RNG, reconfiguration).

Configure the sampler.

Every parameter is checked here, so an invalid one throws from define() rather than from the first draw.

Parameters
kappaSpectral index. Smaller means heavier suprathermal tails; kappa -> infinity recovers the bi-Maxwellian. Must be > 0.5. Note that moments of order l exist only for kappa > (l+1)/2, so for kappa <= 1.5 the loaded population has no finite variance and no convergent temperature.
theta_perpThermal speed transverse to ub, > 0 and finite. It is the scale in the density, a speed rather than a temperature; see Thermal speeds: theta_perp, theta_par for its relation to a temperature.
theta_parThermal speed along ub, > 0 and finite.
ubMagnetic-field direction {bx,by,bz} in the global frame. Need not be normalized; must be non-zero, with a length above about 1.5e-8 in double (3.5e-4 in float); see Field direction: ub. Samples are drawn in the field-aligned frame and rotated into the global frame before return.
max_normalized_velocityVelocity cap in thermal speeds (default 20), or no_cap() for the bi-Kappa distribution itself. A finite value selects a different, bounded target distribution; see The velocity cap. Must be > 0; passing 0 to mean "no cap" throws.
Note
To seed reproducibly, either call seed() afterwards or use the overload taking a trailing int: >= 0 is reproducible, < 0 reseeds from std::random_device. Without either, the stream stays as seeded at construction, which is not reproducible.
Exceptions
std::invalid_argumentif kappa is not greater than 0.5, either theta is not positive and finite, a component of ub is not finite, ub is the zero vector, or max_normalized_velocity is not positive. A NaN in any argument throws. A ub that is non-zero but shorter than the limit above passes define() and makes the first draw throw std::invalid_argument.

◆ n_nonfinite()

template<typename RealType = double>
unsigned long long bi_kappa_distribution< RealType >::n_nonfinite ( ) const
inline

Attempts since the last reset(), define() or seed() whose intended velocity vector had no representation in RealType.

Sufficiently near kappa = 1/2 the bi-Kappa distribution puts non-zero probability outside every finite floating-point range, so such draws exist as mathematics and cannot be returned as numbers. Untruncated mode returns them as non-finite components and counts them here. Capped mode rejects them, as it rejects anything outside the box, and still counts them here, so that a caller can tell "the box rejected a representable sample" from "the box rejected a sample that could not have been returned at all". In both modes the vector whose representability is counted is the velocity the caller would have received, rotation and thermal scaling included – not the normalized coordinate the cap predicate is written in, which understates the largest component whenever theta_par and theta_perp differ. Without this counter the second case is invisible: the returned samples are all finite and the acceptance rate alone does not distinguish the two.

◆ no_cap()

template<typename RealType = double>
constexpr RealType bi_kappa_distribution< RealType >::no_cap ( )
inlinestaticconstexpr

Value of the cap that selects the uncapped sampler: +infinity.

In this mode each draw uses a fixed sequence of variates with no outer acceptance-rejection loop, and the samples follow the bi-Kappa distribution itself.

It must be passed explicitly, because the default cap is 20: 

bi_kappa_distribution<double> d(2.0, 1.0, 2.0, {0,0,1},
                                bi_kappa_distribution<double>::no_cap());

With a finite cap the sampled law is instead that distribution conditioned on all normalized components lying inside the component-wise box – a different, bounded distribution with its own normalization. At kappa <= 3/2 no practical cap value gives a good approximation to the bi-Kappa distribution, and the conditioned distribution is not symmetric under rotation about the field.

The cap is tested in the field-aligned frame, before the rotation into the global frame, so the returned components are not individually bounded by cap*theta unless ub is {0,0,1}; the box rotates with ub. The speed is bounded in every frame, by cap*sqrt(2*theta_perp^2 + theta_par^2).

See also
The velocity cap and The velocity cap for what the capped distribution is, and why a small rejected fraction does not imply a faithful tail.
