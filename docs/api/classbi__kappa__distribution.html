Detailed Description

template<typename RealType = double>
class bi_kappa_distribution< RealType >

Bi-Kappa distribution class for sampling 3D velocity vectors.

This class follows the interface pattern of standard library distributions like std::uniform_real_distribution<T>.

bi_kappa_distribution<double> dist;
dist.define(2.0, 1.0, 2.0, {0, 0, 1}); // kappa, theta_perp, theta_par, ub
auto v = dist(); // {vx, vy, vz}, global frame

Note
The cap defaults to 20 thermal speeds, as in release 1.0.0, so the default target is the bi-Kappa law conditioned on the component-wise box |v_i|/theta_i <= 20. Pass no_cap() to sample the bi-Kappa distribution itself. At kappa <= 3/2 a cap of 20 removes an appreciable part of the tail; see The velocity cap, no_cap() and param_type::capped().
The radius is built in the logarithmic domain. R = sqrt(X1)/sqrt(X2) with X2 ~ Gamma(kappa - 1/2, 1), so as kappa -> 1/2 the denominator's shape goes to zero and X2 underflows to exactly zero. X2 is therefore never formed: the sampler carries log X2 and log R, and reaches the linear domain only at the last step, once per component. Whether a component is representable is then decided from the component itself – the number about to be returned – and never from its logarithm, because log(max()) is a rounded value that can sit on either side of the true limit; see bikappa_detail::materializeComponents. Two consequences a caller should know about:
  • The random stream differs from releases before 2.0.0. The Gamma, normal and uniform primitives are implemented in bikappa_detail rather than taken from <random>, and the direction is drawn by a rejection method that uses no trigonometry, so a given seed produces a different sequence than it used to. In exchange the sequence no longer depends on which standard library is in use: the same seed gives bit-identical output under libc++ and libstdc++, which it did not before – std::gamma_distribution uses a different algorithm in each, and a sin/cos pair on one argument is fused by one compiler and not the other. What the sequence does still depend on is whether the compiler contracts a multiply and an add; pass -ffp-contract=off to pin it to what the source text says. Across architectures nothing is bitwise: log and exp are not correctly rounded and their implementations differ.
  • Non-finite output is still possible, and is now countable. Sufficiently near kappa = 1/2 the bi-Kappa law puts non-zero probability outside every finite floating-point range; those draws exist as mathematics and cannot be returned as numbers. Untruncated mode returns them with non-finite components, as before, and n_nonfinite() counts them. What has changed is how many there are: the loss is now the representability floor of RealType rather than the underflow limit of an intermediate. Measured over 2x10^6 draws at kappa = 0.505 in double, the rate falls from 2.4e-2 to 8.4e-4, which matches the analytic floor.

Configure the sampler.

Validates everything; throws rather than deferring a bad parameter to sampling time.

Parameters
kappaSpectral index. Smaller means heavier suprathermal tails; kappa -> infinity recovers the bi-Maxwellian. Must be > 0.5. Note that moments of order l exist only for kappa > (l+1)/2, so for kappa <= 1.5 the loaded population has no finite variance and no convergent temperature.
theta_perpThermal speed transverse to ub, > 0. A speed, not a temperature: theta = sqrt(2*k_B*T/m).
theta_parThermal speed along ub, > 0.
ubMagnetic-field direction {bx,by,bz} in the global frame. Need not be normalized; must be non-zero. Samples are drawn in the field-aligned frame and rotated into the global frame before return.
max_normalized_velocityVelocity cap in thermal speeds (default 20, as in release 1.0.0), or no_cap() for the untruncated bi-Kappa law. A finite value selects a different, bounded target law – see The velocity cap. Must be > 0; passing 0 to mean "no cap" throws.
Note
To seed reproducibly, either call seed() afterwards or use the overload taking a trailing int: >= 0 is reproducible, < 0 reseeds from std::random_device. Without either, the stream stays as seeded at construction, which is not reproducible.
Exceptions
std::invalid_argumentif kappa <= 0.5, either theta is non-positive or non-finite, ub is zero or has a non-finite component, any of these is NaN, max_normalized_velocity is non-positive, or ub is the zero vector.

◆ n_nonfinite()

template<typename RealType = double>
unsigned long long bi_kappa_distribution< RealType >::n_nonfinite ( ) const
inline

Attempts since the last reset(), define() or seed() whose intended velocity vector had no representation in RealType.

Sufficiently near kappa = 1/2 the bi-Kappa law puts non-zero probability outside every finite floating-point range, so such draws exist as mathematics and cannot be returned as numbers. Untruncated mode returns them as non-finite components, as earlier releases did, and counts them here. Capped mode rejects them, as it rejects anything outside the box, and still counts them here, so that a caller can tell "the box rejected a representable sample" from "the box rejected a sample that could not have been returned at all". In both modes the vector whose representability is counted is the velocity the caller would have received, rotation and thermal scaling included – not the normalized coordinate the cap predicate is written in, which understates the largest component whenever theta_par and theta_perp differ. Without this counter the second case is invisible: the returned samples are all finite and the acceptance rate alone does not distinguish the two.

◆ no_cap()

template<typename RealType = double>
constexpr RealType bi_kappa_distribution< RealType >::no_cap ( )
inlinestaticconstexpr

Sentinel selecting the untruncated sampler.

In this mode the draw uses a fixed sequence of high-level variates with no outer acceptance-rejection loop, and the sampled law is the full bi-Kappa distribution.

It must be passed explicitly, because the default cap is 20 (release 1.0.0): 

bi_kappa_distribution<double> d(2.0, 1.0, 2.0, {0,0,1},
                                bi_kappa_distribution<double>::no_cap());

With a finite cap the sampled law is instead that distribution conditioned on all normalized components lying inside the component-wise box – a different, bounded law with its own normalization. At kappa <= 3/2 no practical cap value is a good approximation to the bi-Kappa law, and the conditioned law is not even axisymmetric about B.

The cap is tested in the field-aligned frame, before the rotation into the global frame, so the returned components are not individually bounded by cap*theta unless ub is {0,0,1}; the box rotates with ub. The speed is bounded in every frame, by cap*sqrt(2*theta_perp^2 + theta_par^2).

See also
The velocity cap for what the capped law is, what it costs, and why a small rejected fraction does not imply faithful tails.

The same rotation, carried out in ValueType.

The basis is a function of ub alone, so evaluating it in the accumulator changes no decision and no stream – it only stops the rotation from spending an ulp of the returned type before the component is formed. With ValueType = RealType this is the rotation used before the wider accumulator was introduced, so a double instantiation is unaffected.
