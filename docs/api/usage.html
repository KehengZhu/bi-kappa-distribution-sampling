Usage Examples

Practical, copy-pasteable recipes for the five samplers.

Every snippet uses Real = double; substitute float or your project's Real as needed. All generators follow the same lifecycle: construct → define(...) → call.

Building and running the demo

The bundled driver runs the test suite and writes 100k samples from each generator to samples_*.txt:

cd cpp
make
./main.exe

Bi-kappa velocity samples

Sample a 3D bi-kappa velocity distribution, anisotropic about the field direction ub, and stream the samples to a file.

#include "bi_kappa_distribution.H"
#include <fstream>
using Real = double;
bi_kappa_distribution<Real> biKappa;
// kappa theta_perp theta_par ub cap seed
biKappa.define(2.0, 1.0, 2.0, {0, 0, 1}, Real(INFINITY), 20030410);
std::ofstream out("samples_bikappa.txt");
for (int i = 0; i < 100000; ++i) {
bi_kappa_distribution<Real>::point_type v = biKappa(); // {vx, vy, vz}, global frame
out << v[0] << ' ' << v[1] << ' ' << v[2] << '\n';
}

Write the cap as bi_kappa_distribution<Real>::no_cap() rather than INFINITY in real code; it is spelled out above only to keep the column alignment readable. The cap is off by default, so biKappa.define(2.0, 1.0, 2.0, {0, 0, 1}) samples the same law — the cap is named here only because the seed has to follow it as the sixth argument.

Warning
The cap selects which of two different distributions you sample — it is not a safety limit on an otherwise unchanged sampler. Omitting it, or passing no_cap(), gives the bi-kappa distribution. Passing a finite value gives a different, bounded law. Read The velocity cap: what it does and how to select it before using one. dist.param().capped() reports which is active.

The velocity cap: what it does and how to select it

Everything you need in order to use the cap correctly is on this page; the accompanying manuscript carries the derivations and the measurements behind the numbers quoted here.

Uncapped is the default

Omitting the argument is enough. These three are identical:

using BK = bi_kappa_distribution<Real>;
BK dist;
dist.define(2.0, 1.0, 2.0, {0, 0, 1}); // omit it
dist.define(2.0, 1.0, 2.0, {0, 0, 1}, BK::no_cap()); // name it
dist.define(2.0, 1.0, 2.0, {0, 0, 1}, std::numeric_limits<Real>::infinity());

no_cap() is +infinity; naming it is worth the keystrokes wherever a reader of the calling code needs to know which of the two laws is being sampled.

Uncapped is not merely a cap large enough to never bind: param_type::capped() is std::isfinite(...), so the sampler skips the acceptance-rejection loop entirely and the core mapping runs exactly once per draw. No rejection, no retry limit, no discarded variates.

To sample the capped law instead, pass a finite positive value. The arguments are positional, so enabling a cap means passing ub as well:

dist.define(2.0, 1.0, 2.0, {0, 0, 1}, 50.0); // bi-kappa conditioned on a 50-theta box
bool c = dist.param().capped(); // true

To go back to the unconditioned law afterwards, assign the sentinel — do not pass 0, which param_type rejects along with every other non-positive value:

dist.max_normalized_velocity(BK::no_cap()); // capped -> uncapped
dist.max_normalized_velocity(0.0); // throws std::invalid_argument

What the capped law is

With a finite cap lam, a draw is accepted only if all three components lie inside the box 

|v_x| / theta_perp <= lam,  |v_y| / theta_perp <= lam,  |v_par| / theta_par <= lam

and is otherwise discarded and redrawn. The result is the bi-kappa density restricted to that box and renormalized — a distribution with bounded support, its own normalization constant, and finite moments of every order even for kappa <= 3/2, where the bi-kappa distribution itself has no finite variance. Those moments are finite because you are sampling a different distribution, not because the cap has repaired the original one. A temperature computed from capped samples is a property of the box as much as of kappa.

Which frame the cap is applied in

The test is performed in the field-aligned frame, before the rotation into the global frame. The box is therefore aligned with ub and rotates with it.

Consequence for calling code: the returned {vx, vy, vz} are not individually bounded by lam * theta unless ub is {0,0,1}. What is bounded, in every frame, is the speed: 

|v| <= lam * sqrt(2*theta_perp^2 + theta_par^2)

which is the corner of the box. Size velocity-grid extents, array bounds, and CFL estimates on that, not on the per-component value.

Normalizing each component by its own thermal speed makes theta_perp and theta_par cancel out of the test entirely. Two practical consequences: the rejected fraction depends on kappa and lam alone, so retuning temperatures never changes your sampling throughput; and the capped law in the local frame is the same law whatever ub you point it at.

What a cap costs you

The rejected fraction is not just a cost — it is the error.** The total-variation distance between the capped law and the bi-kappa distribution equals the fraction of draws you throw away, exactly. There is no trade-off to tune between the two: they are one number.

A small rejected fraction does not mean the tails are right.** At kappa = 1.5 with lam = 50, only 6.3e-4 of draws are rejected, yet the 99.9th-percentile speed of what you keep is 24% too low. If suprathermal particles matter to your problem — and they are usually why a kappa distribution was chosen — judge the cap by the quantiles you care about, not by the acceptance rate.

The box is a cube, so the capped law is not axisymmetric about ub.** A direction pointing at a cube corner has sqrt(3) times more radial room than one along an axis, which imprints a four-fold azimuthal modulation on the distribution function that no choice of theta can absorb. The modulation is easy to miss: the cube's symmetries make the capped pressure tensor exactly gyrotropic and reproduce (theta_par/theta_perp)^2 exactly, so every standard second-order diagnostic returns a clean result while the distribution function itself is not gyrotropic.

For kappa <= 3/2 no practical cap value is a good approximation to the bi-kappa law. If you need bounded velocities there, treat the capped law as the physical model you have chosen and report it as such.

Reproducible runs (seeding)

Each sampler owns an internal std::mt19937. Seed it for byte-for-byte reproducible sequences; re-seeding with the same value restarts the stream.

bi_kappa_distribution<Real> dist;
// (a) seed as the last define() argument (bi_kappa only). The cap cannot be
// omitted here, because the seed is the argument after it:
dist.define(2.0, 1.0, 2.0, {0, 0, 1},
bi_kappa_distribution<Real>::no_cap(), /*seed*/ 55555);
// (b) or seed any time after define() (all samplers):
dist.define(2.0, 1.0, 2.0);
dist.seed(55555); // same seed -> identical sequence
dist.seed(-1); // negative -> unpredictable seed from std::random_device

Sharing one RNG across samplers

Pass your own std::mt19937 to operator() when several samplers should draw from a single stream (e.g. for coordinated reproducibility).

#include <random>
std::mt19937 gen(42u);
bi_kappa_distribution<Real> perp, par;
perp.define(2.0, 1.0, 1.0);
par.define (2.0, 1.0, 5.0);
auto vp = perp(gen); // both consume the same gen
auto vq = par (gen);

Reconfiguring a sampler

Reconfigure everything with define(...), or change one parameter at a time with the convenience setters — each setter re-validates the full parameter set.

bi_kappa_distribution<Real> dist;
dist.define(2.0, 1.0, 1.0); // initial configuration
dist.kappa(5.0); // change one field...
dist.theta_par(2.5); // ...each rebuilds + re-validates
dist.ub({1, 2, 3});
dist.define(3.0, 1.5, 2.5, {0, 0, 1}); // or replace the whole config at once

Custom speed-squared distribution

general_velocity_generator draws a speed from any speed-squared PDF g(w) you supply (by rejection sampling, with w = |V|²) and assigns an isotropic 3D direction, so |V| = sqrt(w). There is no mass parameter: for a distribution originally posed in energy, w = |V|² = 2E/m, so the mass drops out.

#include "general_velocity_generator.H"
#include <cmath>
using Real = double;
auto gW = [](Real w) -> Real { return std::exp(-0.5 * w); }; // any positive g(w), w = |v|^2
general_velocity_generator<Real> velGen;
// g v2_min v2_max
velGen.define(gW, 0.0, 40.0);
velGen.seed(20030410);
general_velocity_generator<Real>::point_type v = velGen();

Field-aligned velocity (anisotropic)

field_aligned_velocity_generator builds an anisotropic velocity about the field direction ub: the parallel component draws v_par² from your speed-squared PDF g(w) (so |v_par| = sqrt(w)), pointing along ub for sign = +1 or opposite it for sign = -1, while the two perpendicular components are a Maxwellian with thermal speed theta_perp (each ~ N(0, theta_perp²/2), the same convention as bi_maxwellian_distribution). The result is returned in the global frame.

#include "field_aligned_velocity_generator.H"
#include <cmath>
using Real = double;
auto gW = [](Real w) -> Real { return std::exp(-0.5 * w); }; // any positive g(w), w = v_par^2
field_aligned_velocity_generator<Real> faGen;
// g v2_min v2_max theta_perp ub sign
faGen.define(gW, 0.0, 40.0, 1.0, {0, 0, 1}, +1);
faGen.seed(20030410);
field_aligned_velocity_generator<Real>::point_type v = faGen(); // {vx, vy, vz}, global frame

Custom spatial density

general_position_generator draws positions in 1D/2D/3D from any density rho(x) by rejection sampling in an axis-aligned box. The returned point is a std::vector<Real> of length dimension.

#include "general_position_generator.H"
#include <cmath>
using Real = double;
using pos_t = general_position_generator<Real>::point_type; // std::vector<Real>
auto rho = [](const pos_t& x) -> Real { return 1.0 + std::sin(x[0]) * std::sin(x[1]); };
general_position_generator<Real> posGen;
const Real pi = 3.14159265358979;
// dim lower upper density
posGen.define(2, {-pi, -pi}, {pi, pi}, rho);
posGen.seed(20030410);
pos_t x = posGen(); // length-2 vector

Error handling

  • The general and field-aligned velocity generators throw std::runtime_error if called before define(...).
  • define(...) throws std::invalid_argument on bad input (e.g. kappa <= 0.5, non-positive theta/cap, v2_min >= v2_max, v2_min < 0, a zero ub, sign other than ±1, dimension outside 1–3).
  • Velocity samplers throw std::runtime_error if the cap rejection loop fails 10⁶ times in a row.
try {
general_velocity_generator<Real> g;
auto v = g(); // not define()d yet -> throws
} catch (const std::runtime_error& e) {
// handle "must be define(...)d before sampling"
}

Complete worked example

The full driver below configures all four generators and writes their samples. See test_suite.H for further patterns (reproducible seeding, cap enforcement, and redefinition).

#include <random>
#include <cmath>
#include <iostream>
#include <fstream>
typedef double Real;
// Local headers
#include "bi_kappa_distribution.H"
#include "bi_maxwellian_distribution.H"
#include "general_position_generator.H"
#include "general_velocity_generator.H"
#include "field_aligned_velocity_generator.H"
#include "test_suite.H"
int main()
{
const Real kappa = 2.0;
const Real theta_perp = 1.0;
const Real theta_par = 2.0;
const int n_particle = 200000;
if (run_all_tests() != 0)
{
return 1;
}
std::cout << std::endl;
std::cout << "=== Example 1: BiKappaDistribution ===" << std::endl;
// Uncapped, so these samples follow the bi-Kappa distribution itself. no_cap() is
// the default; it is named explicitly here because a seed has to be passed as the
// sixth argument, and because the target law is the point of the example. A finite
// cap would instead sample the bi-Kappa law conditioned on a component-wise box --
// a different distribution, and not axisymmetric about B.
bi_kappa_distribution<Real> biKappa;
biKappa.define(kappa, theta_perp, theta_par, {0,0,1},
bi_kappa_distribution<Real>::no_cap(), 20030410);
{
std::ofstream out("samples_bikappa.txt");
for (int i = 0; i < n_particle; ++i) {
const bi_kappa_distribution<Real>::point_type v = biKappa();
out << v[0] << " " << v[1] << " " << v[2] << "\n";
}
std::cout << "wrote " << n_particle << " samples to samples_bikappa.txt" << std::endl;
}
std::cout << "\n=== Example 2: BiMaxwellianDistribution ===" << std::endl;
bi_maxwellian_distribution<Real> biMaxwell;
biMaxwell.define(theta_perp, theta_par, {0,0,1}, 20.0, 20030410);
{
std::ofstream out("samples_bimaxwellian.txt");
for (int i = 0; i < n_particle; ++i) {
const bi_maxwellian_distribution<Real>::point_type v = biMaxwell();
out << v[0] << " " << v[1] << " " << v[2] << "\n";
}
std::cout << "wrote " << n_particle << " samples to samples_bimaxwellian.txt" << std::endl;
}
std::cout << "\n=== Example 3: general_velocity_generator (isotropic Maxwellian via w=|v|^2) ==="
<< std::endl;
// g(w) = sqrt(w) * exp(-w/theta^2) with w = |v|^2 is the speed-squared density
// of an isotropic Maxwellian of thermal speed theta: with dw = 2|v| d|v| it maps
// to the Maxwell speed pdf ~ |v|^2 exp(-|v|^2/theta^2), i.e. each Cartesian
// component is N(0, theta^2/2). theta = theta_perp = 1 here, and w_max = 25
// truncates at |v| = 5 theta.
const Real theta_iso = theta_perp;
auto speedSqPdf = [theta_iso](Real w) -> Real {
return std::sqrt(w) * std::exp(-w / (theta_iso * theta_iso));
};
general_velocity_generator<Real> velocityGen;
velocityGen.define(speedSqPdf,
static_cast<Real>(0.0),
static_cast<Real>(25.0));
velocityGen.seed(20030410);
{
std::ofstream out("samples_general_velocity.txt");
for (int i = 0; i < n_particle; ++i) {
const general_velocity_generator<Real>::point_type v = velocityGen();
out << v[0] << " " << v[1] << " " << v[2] << "\n";
}
std::cout << "wrote " << n_particle << " samples to samples_general_velocity.txt"
<< std::endl;
}
std::cout << "\n=== Example 4: general_position_generator (rho=1+sin(x)sin(y)) ===" << std::endl;
typedef general_position_generator<Real>::point_type position_point_type;
auto rho = [](const position_point_type &x) -> Real {
return 1 + std::sin(x[0]) * std::sin(x[1]);
};
static double pi = 3.14159;
general_position_generator<Real> positionGen;
positionGen.define(2, {-pi, -pi}, {pi, pi}, rho);
positionGen.seed(20030410);
{
std::ofstream out("samples_general_position.txt");
for (int i = 0; i < n_particle; ++i) {
const position_point_type x = positionGen();
out << x[0] << " " << x[1] << "\n";
}
std::cout << "wrote " << n_particle << " samples to samples_general_position.txt"
<< std::endl;
}
std::cout << "\n=== Example 5: field_aligned_velocity_generator (uniform w_par, B=(1,1,1)) ==="
<< std::endl;
// The simplest possible input: g(w_par) = 1 makes w_par = v_par^2 uniform on
// [0, w_max], and the Jacobian dw = 2 v_par d(v_par) turns that into the linear
// ramp p(v_par) = 2 v_par / w_max on [0, sqrt(w_max)]. A density that is flat in
// w is a straight line in v_par -- the clearest illustration of what the change
// of variables does. The perpendicular plane is Maxwellian with thermal speed
// theta_perp, and B is tilted off the axes so the rotation is exercised.
const Real w_max_par = 4.0; // v_par spans [0, 2]
auto parallelSpeedSqPdf = [](Real) -> Real { return Real(1.0); };
field_aligned_velocity_generator<Real> fieldAlignedGen;
fieldAlignedGen.define(parallelSpeedSqPdf,
static_cast<Real>(0.0),
w_max_par,
theta_perp,
{1, 1, 1},
+1);
fieldAlignedGen.seed(20030410);
{
std::ofstream out("samples_field_aligned.txt");
for (int i = 0; i < n_particle; ++i) {
const field_aligned_velocity_generator<Real>::point_type v = fieldAlignedGen();
out << v[0] << " " << v[1] << " " << v[2] << "\n";
}
std::cout << "wrote " << n_particle << " samples to samples_field_aligned.txt"
<< std::endl;
}
return 0;
}
